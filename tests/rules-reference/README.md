# AGENTS.md 引用与规则行为测试

使用 Node.js 内置模块，无需安装依赖。需要本机已有 `codex` 命令；行为测试沿用当前 CLI 配置、默认模型与登录状态，会使用当前账号额度。

## 执行

在规则包根目录执行：

```sh
node tests/rules-reference/run.mjs --static
node tests/rules-reference/run.mjs --all
```

`--static` 不启动模型会话，检查正式规则包的本地引用并运行检查器自测。范围为中央入口、README、docs 与 preferences；不扫描隐藏记忆、测试说明及生成产物。不验证外部网址可用性。本规则包当前使用内联 Markdown 链接；检查器跳过代码块中的示例链接和远程链接，目标路径以引用文件所在目录为基准，允许合法回环，拒绝缺失、空文件和不可读目标。

`--all` 顺序运行 S01、B01–B05 和 E01–E11。每个普通用例启动全新临时会话，不继承其他用例的历史，不向提示词注入应读取清单；E07、E08 保存指定会话并通过明确 session ID 恢复。正常用例依靠全局 AGENTS.md 引导，异常用例明确指定临时规则副本。分析任务只读，代码任务在临时项目内写入；不使用绕过沙箱的选项。

单例每次尝试的模型执行总限时10 分钟，两轮状态用例共享该时间；独立功能断言另限30 秒。规则失败保留证据并复跑一次，基础设施错误不自动重试。可独立诊断一个用例：

```sh
node tests/rules-reference/run.mjs --all --case B01
```

每次运行输出新的临时目录，保留原始日志及项目，不自动删除。普通用例使用 `--ephemeral`；状态用例会留下 CLI 会话记录。确认无需取证后可手动清理运行目录及对应会话。

运行目录保存正式规则初始正文及摘要。每次调用模型前核对正式文件；如果规则在批次中变化，保留修改并停止后续用例，不能把多个输入版本合并成完整通过结论。重新运行 `--all` 建立新基线。

## 证据与判定

解释和汇报必须先读取偏好索引与沟通模块，简单任务同样适用；修改代码前读取技术模块，首次选择或执行测试/验证前读取测试模块。B01/E01/E06 的验证方法及 B03 的验证方案也检查测试模块。E02 检查简短返回仍读取沟通模块，E10/E11 分别隔离纯解释与纯测试选择，同时禁止无关模块加载。

- `static.json`：引用边、回环、可达文件、缺失目标与检查器自测。
- `results.json`：原始机器检查、正式文档摘要及各次尝试。
- `report.md` / `report.json`：汇总结果，首轮失败不因复跑通过而消失。
- `coverage.json`：每个正式规则文件成功全文读取的用例、轮次和事件编号；至少读取过一次不等于所有应加载时机均正确。
- 每次尝试保存原始提示词、调用参数、JSONL 事件、stderr、最终回答、读取证据、修改前后摘要、独立功能断言及验收记录。

修改范围允许对应源码和相关测试文件；B04 同时允许必要的 README 接口说明更新。测试文件名采用限定前缀和扩展名的匹配，避免把合理新增的针对性测试误判为越界。允许修改的文件仍须按 rubric 复核内容是否与任务相关；`existing-user-change.txt` 等无关文件必须保持原样。

读取自动判定只接受成功命令返回的完整正文证据，检查全文而非仅匹配首尾锚点，并核对绝对路径或按 cwd 解析的相对路径。文件名、链接、搜索命中和模型自述均不能单独证明读取。当前解析器主要支持 CLI `command_execution`；MCP、复杂脚本、组合命令非零退出、截断或未识别事件需人工复核，不能据此冒充全部读取成功。路径中的变量和复杂脚本不能可靠归属时，不自动判定读取成功。

工具可能临时切换工作目录，而精简 JSONL 事件未记录该 cwd。完整正文已返回但相对路径无法归属时标记待复核；同一命令中的 `pwd` 可辅助确认。E07/E08 若存在保存的 CLI 会话，另保存 `session-evidence.json`，只摘录本次会话的工具调用输入及来源摘要，供核对真实 workdir，不复制账号元数据或完整系统提示词。

按实际动作核对读取时序：沟通输出前、代码或示例前、首次测试选择/编写/执行前。测试模块不一律要求早于生产代码修改；若修改前已提出测试方案，则必须在提出方案前读取。机器只能可靠核对部分补丁时序，其余结合原始事件逐项复核。只读方案复用缺陷样本时不执行修复后的独立功能断言。

状态为 `PASS`（通过）、`FAIL`（失败）、`BLOCKED`（阻塞）、`NEEDS_REVIEW`（待复核）。内容语义和完整执行时序不使用几个关键词自动判分；必须按 cases.json 中 rubric 查看最终回答与原始事件。自动检查通过时仍保持待复核，直到记录有证据的复核结论。

## 复核

在运行目录的 `reviews.json` 写入已核对的结论。键由用例编号和尝试编号组成，必须写明状态、原因和证据位置，例如：

```json
{
    "B01/attempt-1": {
        "status": "PASS",
        "reviewer": "复核人",
        "notes": "已逐项核对 rubric、文件读取路径和时序，错误解释及验证状态准确。",
        "evidence": ["B01/attempt-1/turn-1/events.jsonl", "B01/attempt-1/turn-1/answer.md"]
    }
}
```

重新生成报告：

```sh
node tests/rules-reference/run.mjs --summarize /绝对路径/运行目录
```

复核必须有 reviewer、说明和存在于该次尝试目录内的证据文件。人工语义通过不能覆盖机器检查中的确定失败或阻塞。无法确认的读取保持待复核；若确认是解析器限制，先修正解析器、增加对应反例测试，再用原始日志重新评估，不能修改原始事件掩盖缺口。

修正解析器后可以重新计算已保存的派生检查，不再次调用模型：

```sh
node tests/rules-reference/run.mjs --reassess /绝对路径/运行目录
```

该操作保留原始事件、回答和修改前后摘要，另外保存旧判定、新判定和解析器代码摘要。应在运行批次结束后执行，避免与运行器同时更新结果文件。正常运行会保存每轮预期文档正文；早期记录若缺少该快照，只能在正式文档摘要仍一致时重建，状态用例按已知测试程序变更还原首轮正文。正式文档已变化且没有历史快照时拒绝重判。

语义复核后发现的失败也只复跑一次，保留在同一个报告中；已经有两次尝试的用例不会再运行：

```sh
node tests/rules-reference/run.mjs --retry-failed /绝对路径/运行目录
```

退出码：静态检查通过为0；完整测试只有全部16 个行为用例及正式文档保护检查通过才为0。失败、阻塞、待复核或只执行部分行为用例为1；参数错误或程序异常为2。

## 边界

本轮只测试本地引用和当前 CLI 条件下的行为，不自动修改正式规则或个人偏好。不宣称覆盖真实上下文压缩恢复、桌面端与 CLI 完全等价或外部网址全面可用性。发现规则缺陷时保留失败输入和证据，再单独提出最小修正建议。

规则或验收条件改变后建立新的运行基线，保留旧批次的输入、原始日志与原判定。不要用新用例配置重新汇总旧批次来宣称旧日志符合新要求。
