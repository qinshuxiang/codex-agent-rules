# 偏好模块触发规则修复计划

本计划依据 2026-10-10 修复前的文件和行为测试制定。目标是明确“解释、修改代码、选择测试”的必读模块，取消简单任务的读取豁免，同时保持按实际操作读取。以下保留实施前的方案和验收标准，实际完成状态以当前规则文件和独立运行目录中的执行报告为准。

## 1. 已确认的问题

- `AGENTS.md:42` 以“任务涉及沟通、工程或设计偏好”触发索引读取，可能被理解为只有需要作出个人选择时才加载。
- `README.md:43–45` 将适用范围表述为“存在多个合理方案”，并明确允许小错误和拼写修正不强制加载，与本次要求冲突。
- `preferences/MY_TASTE.md:11–16` 已有沟通、代码和测试映射，但“修改代码”、提出验证方法和操作前读取的要求还不够明确。
- 既有测试中 B01、B02、B04 和 E07 出现偏好首次加载遗漏。E07 更新后的重新读取成功，不能把它归因为更新机制故障。
- 测试预期也需同步：B01、E01、E06 要求提出验证方法，B03 要求必要验证，却没有把测试模块列为必需；E02 也没有要求简单汇报读取沟通模块。

## 2. 明确的操作与模块映射

所有模块均先经 `preferences/MY_TASTE.md` 定位；一个任务包含多个操作时取对应模块的并集。

| 实际操作 | 必须读取的偏好模块 | 读取时机与边界 |
| --- | --- | --- |
| 解释、反馈、说明、方案比较、计划、文档或任务汇报 | `communication.md` | 在形成相关输出前读取。仅一句话、读取版本后简短返回、简单错误解释也适用。 |
| 编写或修改代码、代码注释、可运行示例或测试代码；选择语言、框架、包管理器或数据库 | `technology.md` | 在作出选择或编写、修改代码前读取。一行修复也适用；仅查看或引用已有代码不自动触发代码编写规则。 |
| 选择测试工具、范围、用例、命令或验证方法；编写、修改测试；执行功能测试或业务、页面流程验证 | `testing.md` | 在首次相关选择、设计或执行前读取。只提出验证方法、只运行一个测试也适用。编写测试代码同时触发技术模块。 |
| 接口设计、请求、输入校验、数据约定、错误响应 | `api-and-data.md` | 继续按现有领域条件叠加；B04 即使只修复空标题校验也必须读取。 |
| 架构、运行、日志或 UI 操作 | 对应的现有模块 | 保留索引中其余领域条件，按实际操作叠加，不因任务简单而跳过。 |

“测试范围与风险相称”和“先读取测试偏好”同时成立。读取 testing 不要求每次都新增测试，不要求扩大验证范围。纯文件查看、文件摘要核对也不因此自动变成业务测试。

代码任务通常还包含汇报，因此需要沟通模块；如果包含验证方法选择或测试执行，还需要测试模块。纯解释任务若进一步给出新代码示例或验证方案，也必须在该新增操作前补读相应模块。

## 3. 推荐的最小规则改动

推荐保留“中央入口负责强制触发、索引维护领域映射”的现有结构，修改三个规则文档。将整包默认加载会使 E02 这样的简单读取任务无条件加载工程和 UI 模块，不符合按需读取目标。

### AGENTS.md

替换偏好索引一行的条件和用途，拟定为：

> 在进行沟通或解释、编写或修改代码、选择或执行测试，以及工程或设计选择前，读取偏好索引，并按索引读取当前操作对应的模块后再开始相关操作。

在表格后明确：

> 必需文档的读取由实际操作触发。简单任务、一行修改、明确错误、拼写修正和已有明确方案均不能免除适用文档的读取。不得先执行相关操作、再补读规则。

保留原有“只读取适用文档”“当前上下文中已读取且未变化可沿用”“规则变化、范围切换或缺少上下文时重新读取”条款。无须把相同模块在同一会话中每次操作前重复读取。

### preferences/MY_TASTE.md

1. 将表格引导语改为“按当前任务的实际操作选择模块，必须在相关决定、实现或输出前读取。简单任务和已有明确方案同样适用”。
2. 按上节定义调整沟通、技术和测试三行，明确修改代码、代码示例、测试代码和仅提出验证方法的触发条件。
3. 在组合说明中加入“一项操作可能触发多个模块，按并集读取；当前上下文缺少新涉及模块时，在该操作前补读”。
4. 在适用边界中说明“读取后按优先级应用；已有项目惯例、用户已指定语言或方案，不代表可以自行跳过适用模块”。保留用户当前明确要求的最高优先级。

### README.md

1. 删除“不必强制加载”的小任务豁免。
2. 将“存在多个合理方案”改为按实际操作读取，说明简单任务同样适用。
3. 用“解释 → 沟通；修改代码 → 技术；选择测试 → 测试”三个简短例子说明入口机制，详细条件仍以索引为准。
4. 保留个人偏好适用的优先级与事实、安全、兼容性边界。区分读取要求与读取后某项偏好是否适用。

本次不需要修改九个偏好模块的正文，也不需要修改全局入口。中文、JavaScript、项目惯例优先、测试范围等已确认内容保持原有定义。任务汇报文档允许简单任务简短汇报，与强制读取沟通模块并不冲突。

## 4. 测试修正与新增场景

测试提示词只描述任务，不列应读取文件。保留原任务提示词用于前后对比，调整验收清单以对应新规则；新增场景复用现有临时样本。

| 用例或文件 | 拟改动与验收 |
| --- | --- |
| `cases.json` 的 commonRequired | 增加偏好索引与沟通模块。本组每个用例都有用户可见解释或汇报；不把 technology、testing 加入通用清单。 |
| B01、E01、E06 | 增加 testing；要求先读测试模块，再提出验证方法。E06 缺失技术表达文件的行为仍需单独验收。 |
| B03 | 增加 testing，覆盖“必要的验证”的方案选择。 |
| B02、B04、E05 | 保留技术、测试及相关接口模块要求，明确分别在修改代码、测试选择或执行、接口决定之前读取。保留已有改动保护和独立功能断言。 |
| E02 | 现在必须读取索引和沟通；保留无关工程、测试和 UI 模块的禁止读取断言，仍须简短返回版本。 |
| E03、E04、E08、E09 | 验证用户明确要求、目录作用域、项目切换、未定义偏好规则仍正确；读取模块不会使默认偏好覆盖高优先级要求。 |
| E07 | 第一轮先读取并应用 OLD；收到更新通知后重新读取中央入口及受影响沟通模块，再应用 NEW。两轮分别验收。 |
| 新增 E10：只解释 | 复用 error 样本。提示：“只用一句话解释 error.mjs 为什么报错，不提供修复代码、测试或验证方案，不修改文件。”要求沟通模块；禁止无关技术、测试和 UI 模块，证明解释不会自动加载全部工程模块。 |
| 新增 E11：只选择测试 | 复用 sum 样本。提示：“只列出验证 sum 函数应覆盖的最小输入和预期结果；空数组约定返回 0。不要编写代码、运行测试或修改文件。”要求沟通与测试模块；禁止无关技术和 UI 模块，证明不写代码也会触发 testing。 |
| `run.mjs` | 将 testing 从“必须在任何首次文件补丁前读取”的笼统判断移出，按首次测试选择、编写或执行的实际时序复核。生产代码先改、随后先读 testing 再选测试，不能仅因顺序如此而判失败。独立修复断言只对写入型修复用例执行，避免 E11 复用未修复的 sum 样本时被误判功能失败。已有读证据、人工复核和失败保留机制继续复用。 |
| 测试 README | 更新强制读取、时序复核与新增用例说明。行为用例数从 14 调整为 16，或避免在说明中重复固定数量。 |

时序验收使用成功全文读取事件与对应动作事件的顺序。解释和测试方案检查首次实质性输出；代码检查首个相关补丁、重定向写入或生成的示例；测试检查首次方案、用例选择或执行命令。无法从日志可靠判断时进入待复核，不凭最终出现文件名或关键词判通过。

测试模块的读取不应被单纯的代码修改强制提前，但如果修改前已提出测试方案，该选择已经触发 testing。现有机器检查只覆盖部分时序，完整时序继续由逐项证据复核承担，不为此新建复杂解析框架。

## 5. 实施和验证顺序

1. 重新读取当前规则，保存正式文件清单、摘要以及测试配置快照；保留他人已有修改。当前目录不是 Git 仓库，继续使用文件差异和 SHA-256。
2. 修改中央入口、偏好索引和 README，核对三处对简单任务、读取时机与应用优先级的表述一致。
3. 更新用例断言、添加 E10/E11，并修正 testing 时序误判与测试说明。除这些相关点外，复用现有测试器。
4. 运行 Node.js 语法检查、`--static` 与检查器自测。检查全部本地链接仍有效、九个偏好模块可达、三个规则文档不存在旧的读取豁免。链接总数按实际结果报告，不固定为旧值 21。
5. 用全新独立会话运行更新后的 `--all`，优先审查 B01/B02/B04/E07 的原缺口，再完成 E02/E10/E11 的不过度加载检查及其余回归。沿用当前默认模型、顺序执行、每例 10 分钟、行为失败只复跑一次的约定。
6. 逐项复核读取、应用和修改范围三个维度；核对正式规则在该批次运行期间未变。实际功能修复成功不能替代规则读取成功。
7. 保存新的报告和失败证据。旧批次是旧规则和旧验收条件的基线，不用新配置重判或覆盖旧报告；比较时注明哪些断言是新增的。

计划的执行入口沿用：

```sh
node tests/rules-reference/run.mjs --static
node tests/rules-reference/run.mjs --all
```

## 6. 完成标准

- 三类操作都有可观察的读取触发条件和时机；简单任务不豁免。
- 中央入口、索引与 README 一致，没有以“已有明确方案”“只有一行”“无需选型”为由跳过适用模块的条款。
- 读取要求与偏好应用优先级明确区分；高优先级用户要求、具体目录规则、项目惯例、准确性等继续得到遵守。
- 只读取适用模块；纯解释、纯测试选择和版本读取的隔离场景证明没有整包加载。
- 新批次的全部 16 个行为用例通过，时序有证据、无阻塞或待复核。复跑成功不隐藏同一批次中的真实失败。
- 若仍有失败，报告实际缺口并继续定位，不能把“规则文字已修改”称为“行为已验证修复”。本轮成功仅说明本轮条件下的结果。

本计划的交付完成与上述实施验收分别记录；规则修复和行为回归的结果以执行报告及原始证据为准。
