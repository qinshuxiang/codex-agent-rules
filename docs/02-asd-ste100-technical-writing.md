# 技术表达：清晰写作与合适的形式

目标是降低读者理解、判断和操作的成本。适用于技术解释、文档、计划、注释、错误分析和任务总结。文字借鉴 ASD-STE100 的清晰表达原则，不要求正式合规。

## 写清楚

- 先给结论或要点，再解释必要的原因和细节。篇幅随问题复杂度调整，简短不能省略关键条件、证据或限制。
- 使用常见、具体的词语。同一概念保持同一名称；文件名、标识符、命令和配置键保留原样。专业术语首次出现时按需解释。
- 一句话表达一个主要意思，明确主体、动作和对象。复杂内容按条件、动作和结果拆开，保留因果与例外，避免含糊指代。
- 区分已确认事实、推断、假设和建议。结论给出必要依据；不确定时说明具体缺口，不用程度词代替证据。
- 需要帮助理解时，给一个贴近当前项目的例子。操作说明提供必要步骤和成功标准，避免“适当调整”“确保正常”等空泛指令。

## 选对形式

选择能明显降低理解成本的最简单形式，可组合使用：

- 文字：说明结论、原因、条件和操作。
- 表格或图示：比较选项、展示结构、流程、关系、趋势和数量；简单问题不强行配图。
- 交互网页：当调整参数、切换情景或逐步演示有助于理解时使用，优先复用现有能力。
- 视频：用户明确需要连续演示或配音讲解时使用；制作前确认必要工具、资源及费用。

图示和演示须与事实一致，示意内容应明确标注。删去不帮助理解的装饰和重复说明。
