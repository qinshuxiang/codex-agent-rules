# 架构与代码组织偏好

- **架构和复杂度偏好**：所有项目默认统一保留前端和后端，采用前后端分离架构。即使当前功能可以仅由前端完成，也保留后端工程。前端负责界面与交互，后端负责服务逻辑与接口。新建项目及已有项目中允许选择实现方式的新增部分，默认采用适度分层的工程组织方式，明确界面展示、请求处理、业务逻辑和数据访问的职责。按当前功能的复杂度和复用需求拆分模块，避免将复杂业务集中在页面组件或接口处理函数中。简单逻辑允许合并实现，不为满足固定层数而增加空目录、转发函数或抽象层。已有项目遵循原有架构，确需调整时说明原因和影响范围。

- **前后端目录命名**：新建项目时，前端目录默认使用 `client/`，后端目录默认使用 `server/`。

- **前端代码组织**：区分页面、可复用 UI 组件、接口调用和可复用业务逻辑。页面负责组织展示与交互；可复用组件通过明确的输入和事件与外部协作；重复或复杂的组合逻辑按需提取为 composable。局部状态优先保留在所属组件中，存在跨组件或跨页面共享需求时再提取共享状态。

- **后端代码组织**：区分接口处理、业务逻辑和数据访问。接口处理负责读取请求、调用校验和业务函数，以及返回响应；业务逻辑负责业务规则和流程；数据访问负责数据库或本地文件的读写。复杂或重复的逻辑提取为独立函数或模块。简单接口允许合并部分实现，不要求每个接口机械地经过所有层级。

功能实现兼顾本地使用与后续维护；职责、接口和错误处理清楚，并覆盖主要业务与页面流程的验证。模块与抽象按当前需求增加。
