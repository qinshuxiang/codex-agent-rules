# 我的习惯、风格与品味

本文件是个人偏好的统一索引。具体偏好在下列模块中维护，每项偏好只保留一份正文。

## 按任务读取

按当前任务的实际操作选择模块，必须在相关决定、实现或输出前读取。简单任务和已有明确方案同样适用。引用路径以本文件所在目录为基准。

| 任务或选择 | 读取模块 |
| --- | --- |
| 沟通、解释、反馈、方案比较、计划、文档、简短结果说明或汇报 | [沟通与写作](communication.md) |
| 选择语言、框架、包管理器或数据库；编写或修改代码、代码注释、代码示例或测试代码 | [技术栈与代码风格](technology.md) |
| 新建项目、组织前后端目录、划分模块职责或调整架构 | [架构与代码组织](architecture.md) |
| 接口设计、前后端请求、输入校验、数据约定或错误响应 | [接口、请求与数据](api-and-data.md) |
| 确定本地使用范围、登录权限需求、运行部署、交付步骤或日志方案 | [本地运行、部署与日志](runtime-and-logging.md) |
| 选择测试工具、范围、用例、命令或验证方法；编写或修改测试；执行功能测试或业务、页面流程验证 | [测试与验证](testing.md) |
| 选择界面风格、主题、字体、配色或信息密度 | [界面视觉风格](ui-style.md) |
| 开发、引入或调整 Vue UI 组件、复合组件或 Blocks | [组件与页面复用](ui-components.md) |
| 设计页面布局、表格、图表、登录注册页面或交互状态 | [布局、数据展示与交互](ui-layout-and-interaction.md) |

一个任务包含多种操作时，读取对应模块的并集；新增操作涉及尚未加载的模块时，必须在该操作前补读。例如，解释错误并提出验证方法需要沟通和测试模块；编写测试代码还需要技术模块。Vue 页面开发通常涉及技术、视觉、组件和布局模块，涉及请求或测试时再读取对应模块。

仅查看或引用已有代码不自动触发代码编写规则；纯文件查看和文件摘要核对不自动视为功能测试。读取测试模块不要求增加无关测试，验证范围仍与风险相称。内容已在当前上下文中且未变化时可沿用，不要求每次操作读取所有模块。

## 适用边界

- 只将用户明确确认的内容视为个人偏好。未记录的偏好尚未定义，不能自行补全，也不能把示例或工程底线当成个人选择。
- 规则优先级、代码风格与项目惯例的关系，以及偏好不能覆盖的底线，按 [中央规则](../AGENTS.md) 执行。
- 必须读取适用模块，再按优先级应用。已有项目惯例、用户已指定语言或方案，不代表可以自行跳过适用模块；用户当前明确要求的优先级保持不变。
- 当偏好缺失时，遵守项目惯例与通用工程规则；仍需作出偏好选择时，先向用户询问。
- 当偏好冲突时，优先采用更具体、更新且适用于当前任务的偏好；无法确认先后关系时不得猜测，影响重大时指出冲突。

## 更新规则

- 可以建议记录值得长期保存的新习惯，但必须经用户明确确认后才能新增、修改或删除偏好。
- 只更新用户指定的条目，保留其他已确认信息；拆分或移动条目时同步更新索引与引用。
- 在所属模块维护偏好正文，索引只说明读取条件；不在多个模块中复制同一项偏好。
- 用户要求删除某项偏好时删除对应内容，不保留不必要的副本。不保留维护历史或空白占位。
- 不保存密码、令牌、私钥等凭据或敏感个人资料。公开发布或共享前检查全部偏好模块；需要保密时移到私有位置，并同步调整引用。
