## 个人品味何时生效

- **读取条件**：按实际操作读取偏好索引及相关模块，必须在对应操作前完成。解释、反馈或汇报读取沟通模块；编写或修改代码读取技术模块；选择测试或验证方法读取测试模块。详细条件以偏好索引为准，多种操作取模块并集。
- **简单任务**：一句话解释、一行修复、明确错误、拼写修正和已有明确方案也必须读取适用模块；只读取当前操作涉及的模块。
- **覆盖边界**：已确认的相关偏好可覆盖默认表达和汇报形式；代码风格与项目惯例的关系按 `AGENTS.md` 执行。
- **应用边界**：读取后按优先级和实际条件应用。偏好尚未记录，或者与用户明确任务、安全性、正确性、兼容性等冲突时，不能自行补全或强行应用。

## 隐私与共享

个人品味文件可能包含个人信息。公开发布或上传仓库前，请检查 `preferences/` 下的全部偏好文件。如需保密，可将个人偏好保存到私有位置，再按实际部署方式调整规则引用。

## 设计原则

1. **Karpathy**：怎么执行任务。
2. **技术表达**：借鉴 ASD-STE100 清晰写作，并按理解需要选择文字、图表、交互网页或视频（不要求正式合规）。
3. **汇报与验证**：怎么证明任务完成。
4. **我的品味**：在多个可行方案之间，怎么选出更符合我习惯和风格的结果。

偏好不是事实；尚未记录的内容不能由 Codex 自行推定。

## 读取与维护

每个新任务开始时读取中央 `AGENTS.md`；规则发生变化、工作范围切换或缺少相关上下文时重新读取。按入口和偏好索引的操作条件读取所需文件，不以任务规模决定是否读取，也不要求每次操作加载全部文档。当前上下文已读取且未变化的内容可以沿用。

中央入口中的相对路径以中央入口所在目录为基准，偏好索引中的相对路径以 `preferences/` 为基准。跨项目使用时，仍从中央规则包定位引用文件。

偏好正文只在所属模块维护；调整模块时同步更新索引。不保留维护历史或空白占位。
